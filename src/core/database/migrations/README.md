# Database Migrations Workflow

This directory stores SQL migration files generated by Drizzle Kit and tracks schema changes for the local Expo SQLite database.

## 1. Directory Structure

- `meta/_journal.json`: Internal Drizzle Kit journal tracking migration versions and breakpoints.
- `manifest.ts`: TypeScript manifest registering bundled migration statements for runtime execution on mobile devices.
- `0000_*.sql` (future): Generated SQL statements produced by Drizzle Kit.

## 2. Generating Migrations

When entity schemas in `src/core/database/schema/` are added or updated:

1. Run the migration generator script:
   ```bash
   npm run db:generate
   ```
2. Drizzle Kit reads `drizzle.config.ts`, compares schema definitions against the snapshot in `meta/`, and generates new SQL migration statements.

## 3. Registering & Bundling Migrations

Because React Native/Metro does not bundle raw `.sql` files without custom loaders, map newly generated migration statements in `src/core/database/migrations/manifest.ts`:

```typescript
export const migrationsManifest: MigrationManifest = {
  journal: journal as unknown as MigrationManifest['journal'],
  migrations: {
    // Example: m0000: require('./0000_create_tasks.sql'), or inlined string
  },
};
```

## 4. Applying Migrations

### Programmatic Application
Use `applyMigrations()` during application bootstrap (e.g., in `_layout.tsx` before rendering application screens):

```typescript
import { initializeDatabase, applyMigrations } from '@/core/database';

async function bootstrap() {
  initializeDatabase();
  await applyMigrations();
}
```

### Hook-Based Application
Alternatively, use `useMigrations` from `drizzle-orm/expo-sqlite/migrator`:

```typescript
import { useMigrations } from 'drizzle-orm/expo-sqlite/migrator';
import { db, migrationsManifest } from '@/core/database';

export default function RootLayout() {
  const { success, error } = useMigrations(db, migrationsManifest);
  // Render loading splash until success === true
}
```

## 5. Rules & Persistence Guarantees

- **Local Storage Sandbox**: The database file (`ai_calender.db`) is stored exclusively in the application's local sandbox (`Documents/SQLite` on iOS, `databases/` on Android).
- **Restart Persistence**: Data persists across application restarts and OS reboots.
- **No Remote Sync**: No automatic background synchronization occurs between devices.
- **App Uninstall**: Uninstalling the application deletes the sandbox directory and all local database files.
- **Timestamps**: All timestamps must be stored in UTC format (ISO 8601 strings or epoch integers). Localization (e.g., Jalali calendar) occurs strictly at the presentation boundary.
- **Immutability**: Never manually modify generated migration files.
